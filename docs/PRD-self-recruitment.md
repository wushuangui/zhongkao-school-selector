## 1. 产品定位与价值主张

### 1.1 一句话定位

**面向深圳初三（及初二升初三）家庭的中考升学决策助手**：在官方政策框架下，用「分数线 + 招生路径 + 学校画像」帮助家长回答「分够哪些路、怎么走、花多少钱、自招值不值得冲」。

### 1.2 价值主张

| 维度 | 对家长的承诺 |
|------|----------------|
| 可信 | 数据链到深圳市教育局 / 深圳招考网；规则与推荐附来源与免责声明 |
| 可算 | 预估分、分差、分段筛选、「只看达到我的分数」 |
| 可对比 | 最多 3 校横比（自招控制线、名额分配资格线、一批线、计划、学费等） |
| 可懂 | 区分资格线与录取线；自招合成总分 60%+40% |
| 可传播 | URL 分享筛选状态；单文件 HTML 适合微信转发 |

### 1.3 产品边界

- **不替代**志愿填报系统；**不承诺**录取。
- 聚焦信息整合、筛选、解释与可执行清单辅助。
- 覆盖路径预习：统招、自主招生、名额分配（指标）、第二批/二次划线/第三批、民办收费对照。

### 1.4 愿景（V3 北极星）

家长输入 **平时 / mock 分数区间** → 获得 **冲 / 稳 / 保** 学校清单与路径组合说明（统招 / 自招 / 指标 / 预算），并随政策节点刷新内容与数据时效标识。

## 2. 目标用户与核心场景

### 2.1 用户分层

| Persona | 特征 | 核心诉求 |
|---------|------|----------|
| P1 决策型家长 | 首次系统了解深圳中考 | 懂批次与名词、建立分数段位感 |
| P2 特长型家长 | 一类理工/人文或二类艺体 | 筛学校与项目、看控制分、估自招性价比 |
| P3 预算敏感家长 | 考虑民办/跨区 | 学费三年合计、公办标准、批次线对照 |
| P4 信息焦虑家长 | 临近报名怕漏节点 | 时间轴、渠道、「1 校 1 项目」硬约束 |
| P5 协调人 | 班群转发、答疑 | 可分享链接、规则说明、单文件离线包 |

### 2.2 核心用户故事（摘要）

| ID | 故事 | 现况 |
|----|------|------|
| A | 按预估分摸底一批可达学校 | 支持单值「我的中考分」与分差；**缺** mock 映射与志愿梯度模板 |
| B | 自招项目筛选与 3 校对比、合成总分估算 | **已实现**（一类/二类、学科、按项目看、规则计算器） |
| C | 理解自招控制分 ≠ 一批录取线 | **已实现**（`rules.js`、卡片三线对照） |
| D | 名额分配资格线查询 | **已实现** Tab；**缺**校内指标资格专题 |
| E | 二批 / 补录资格线与官方原图 | **已实现** |
| F | 收费标准与三年合计 | **已实现** |
| G | 分享筛选状态 | **已实现**（URL 参数 + hash） |

## 3. 产品决策记录（已锁定）

> **本节为干系人已确认决策，后续 Roadmap、推荐引擎与 Issue 拆分须以此为约束，未经正式评审不得推翻。**

| # | 决策 | 含义与执行要点 |
|---|------|----------------|
| **D-1** | **V2 起坚持纯静态架构** | 不建设订阅/账号后端；形态为 **静态 H5 + 数据管线（Python 抓取/构建）+ GitHub Actions / Pages 发布**。政策与数据更新通过 **发版 + 页脚/公告区展示 `fetchedAt`**；用户触达依赖 **公众号/社群/单文件转发**，不做 V3.1 式「订阅推送服务」。 |
| **D-2** | **推荐引擎默认「保守档」** | 首次进入推荐/梯度能力时，映射与志愿池 **默认保守**（等价于区间下沿 + 较大不确定性）；用户可手动切至中性/乐观。**禁止**默认展示进攻型冲档；输出用语为冲/稳/保 **档位**，非录取概率 %。 |
| **D-3** | **不做 D 类 / 港澳家庭简版** | 不在 IA 上增设「港澳/D 类专项简版」或独立多语言简版站点。现行 **AC/D/ACD 分数线筛选** 保留；文案仅引用官方分类，**不作**户籍/跨境政策判断或专项向导。 |
| **D-4** | **与仓库内其他子应用统一品牌与数据层** | 产品名、视觉令牌（主色、页脚声明）、数据来源字段 schema（`year`、`fetchedAt`、`source`）、校名归一与 `supplement.json` 修正流程 **与 monorepo 内兄弟应用对齐**；新建能力优先 **复用共享数据构建脚本与命名规范**，避免重复抓取与校名分裂。 |

**明确排除（除非政策与合规另行评审）**：志愿系统自动投档模拟、官方 API 对接、付费「保录取」、为推送而引入的后端与用户账号体系。

## 4. 现状评估

### 4.1 成熟度

**当前 = MVP+**：三 Tab（自主招生 / 录取分数线 / 收费标准）+ 规则与合成总分计算器 + 最多 3 校对比 + 数据脚本 + 静态部署，已达可用工具水准。

### 4.2 已实现能力清单

| 模块 | 要点 |
|------|------|
| 自招 | 一类/二类、赛道/学科、筛选排序、按项目看、分差与分段 |
| 分数线 | 名额分配、一批、二批、二次划线、三批；类别与说明/原图 |
| 收费 | 公办标准与民办排序 |
| 规则 | 报名/录取/线别名词、官方链接、计算器 |
| 数据 | `fetch_data.py`、`fetch_scores.py` → `*-data.js` |
| 部署 | GitHub Pages workflow、`build_single.py`、`deploy.ps1` |

### 4.3 缺口（相对愿景）

1. 平时分 / mock → 预估中考分（区间与来源标注）  
2. 升学路径专题与全年政策时间轴（静态内容）  
3. 冲稳保推荐与志愿梯度模板（规则可解释、默认保守）  
4. 政策变更 **diff 公告**（静态页/CHANGELOG，非推送订阅）  
5. 数据 schema 强化（`scoreKind`、年度字段页内显性化）  
6. 可选轻量埋点（须符合纯静态，如 Umami/自建 beacon）

### 5.1 目标信息架构

```

│   ├── 录取分数线
```

**V1 最小增量**：在导航增加 **「填报指南」**（或等价命名），与三 Tab 并列；品牌命名遵循 **D-4**。

### 5.2 模块关系（逻辑）

- **展示层**：静态 H5、`rules.js`、URL/单文件分享

- **管线层**：抓取 → 校验 → 构建 JS bundle → CI 部署  
- **未来（纯前端）**：映射引擎 + 推荐引擎（规则 JSON/WASM，无服务端）

## 7. 数据与内容体系（SOP 摘要）

### 7.1 数据来源

| 类型 | 权威来源 | 产物 |
|------|----------|------|
| 自招计划与控制分 | 市教育局通知 docx | `zzzs-*.json` → `zzzs-data.js` |
| 各批次分数线 | 深圳招考网 | `scores-*.json` → `scores-data.js` |
| 学校画像/收费 | 招考网介绍、发改标准、学校公示 | profiles / fee |
| 人工修正 | 运营 | `supplement.json`（跨应用共享约定） |

### 7.2 质量规范

- 校名归一与 **别名表** 仓库级维护（**D-4**）。  
- 分数须标注语义：`资格线` / `录取线`（schema 强制）。  
- 页脚与筛选区展示 **`year`、`fetchedAt`、`source`**。  
- 保留官方划线原图路径，应对录入争议。

### 7.3 更新 SOP（5 步）

1. **监测**：教育局/招考网栏目；升学季 5–7 月、7–8 月补录加密度  
2. **抓取**：`scripts/fetch_data.py`、`fetch_scores.py`（`deploy.ps1 -Refresh`）  
3. **QA**：样本校三线对照、民办收费、二类双控制分  
4. **发布**：合入主分支 → CI 部署；单文件 HTML 供社群；**静态「更新公告」**（含 diff 摘要）  
5. **回滚**：Git 版本化 JSON；保留上一年度供趋势

## 8. 推荐引擎（保守默认为准）

### 8.1 原则

- **可解释**：每条建议附规则 ID + 数据字段。  
- **保守表述**：档位标签，非录取概率承诺（**D-2**）。  
- **多路径并行**：文案提示自招录取后批次作废等互斥规则。

### 8.2 三层架构

1. **硬约束**：AC/D 可比线集合；自招 1 校 1 项目；`中考分 ≥ 控制分`；预算上限（民办三年合计）。  
2. **分数映射**：`μ = a·mock + b`；区间由 mock 类型查表 σ；**默认取保守端点（μ − σ 或等价 preset）**。  
3. **排序与池化**：进攻/均衡/保守/预算 preset；**产品默认加载保守 preset**；用户切换中性/乐观需二次确认风险提示。

### 8.3 输出

- 学校卡片：冲 / 稳 / 保 / 仅自招 / 不推荐。  
- 方案页：统招候选池 + 至多 1 所自招备选 + 法定免责声明文案。  
- 与现网衔接：扩展 `shared.myScore` 为 `{ point, low, high, source, riskPreset }`。

## 9. 合规与免责声明

- 定位：公开信息整理工具，非招生广告。  
- 禁止：包录、内部指标、降分运作等表述。  
- 强制展示（页脚 + 推荐/梯度页）：数据来源、年度差异、推荐非法律依据、简章与主管部门为准。  
- AC/D 等政策话题：**链官方原文，不做法律解释（D-3 延伸）**。  
- 数据滞后：**显著 `fetchedAt`** 与「更新中」状态（纯静态，无推送）。

## 10. 成功指标

### 10.1 北极星

升学季内 **有效选校探索** 会话数（输入预估分并使用「只看达到」/ 2 校以上对比 / 规则停留 >30s / 导出清单）。

### 10.2 过程指标

| 类别 | 指标 |
|------|------|
| 传播 | 带参 URL 二次打开、单文件打开 |
| 价值 | 对比率、规则打开率、填报指南阅读深度 |
| 质量 | 纠错闭环时长、数据 diff 修复 SLA |
| 交付 | 政策发布后 24–72h 内静态发版完成率 ≥95% |

### 10.3 反面指标

- 「自招控制分当一批线」类咨询量（V1 FAQ 目标下降）。  
- 大 bundle 导致低端机卡顿流失。

## 11. 技术方案（纯静态）

| 项 | 选型 |
|----|------|
| 前端 | 原生 HTML/CSS/JS，无构建链 |
| 数据 | 全局 `*.js` 数据集 |
| 后端 | **无**（**D-1**） |
| 管线 | Python 抓取/构建 |
| 部署 | GitHub Actions Pages；可选 Cloudflare；`build_single.py` |
| V2+ 推荐 | 纯前端 JS/规则 JSON；可选懒加载多年度数据 |

### 非功能需求（摘要）

- 4G 首屏可交互 <3s（大 JSON 为技术债，V2 考虑分 batch 懒加载）。  
- 移动优先；`escapeHtml` 与对话框 a11y 持续加强。  
- 隐私：预估分仅存本地/URL，不上传服务端（无后端）。

## 12. 风险与依赖

| 风险 | 缓解 |
|------|------|
| 官方栏目/格式变更 | 人工兜底、保留 raw、静态「更新延迟」说明 |
| 录入错误 | QA、用户纠错、免责声明 |
| 政策大改 | 规则配置化、快速发版 |
| 无推送后端导致触达弱 | 公众号/社群 SOP、单文件、发版公告（**D-1** 接受） |
| 保守默认被指「不够激进」 | 明示可切换档位 + 可解释依据（**D-2**） |
| monorepo 品牌分裂 | **D-4** 统一设计令牌与数据 schema |

**依赖**：教育局/招考网可访问；Pages 或单文件传播通道；至少 2 人角色（政策监测 + 数据 QA）。
